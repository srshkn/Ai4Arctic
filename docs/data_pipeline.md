# Pipeline подготовки данных

Полная цепочка от спутниковых данных до входного тензора `tensor_01deg_v2.npz`.

## Общая схема

```
┌──────────────────────────┐
│ Google Earth Engine      │  20 признаков, 14 лет, 2 тайла (west/east)
│ (gee.ipynb)              │
└────────┬─────────────────┘
         │  выгрузка 56 .geojson
         ▼
┌──────────────────────────┐
│ merge_geojson_bands.py   │  объединение band1+band2, west+east
└────────┬─────────────────┘
         │  14 merged.geojson
         ▼
┌──────────────────────────┐
│ rasterize_to_tensor.py   │  растеризация на сетку 0.1° × 0.1°
└────────┬─────────────────┘
         │  массив (14, 231, 1501, 20)
         ▼
┌──────────────────────────┐
│ compute_ttop_target.py   │  расчёт target по формуле TTOP
└────────┬─────────────────┘
         ▼
   tensor_01deg_v2.npz
   (X + y + метаданные)
```

## Источники данных

| Источник | Что берётся | Разрешение оригинала | Доступ |
|---|---|---|---|
| MODIS MOD11A1 / MYD11A1 | LST_summer, LST_winter, LST_annual, FDD, TDD | 1 км, ежедн. | GEE |
| MODIS MOD13Q1 | NDVI, NDWI, NDMI, SAVI | 250 м, 16 дней | GEE |
| MOD10A1 | snow_days | 500 м, ежедн. | GEE |
| ERA5-Land | era5_temp, era5_precip | 0.1°, ежечасно | GEE |
| WorldClim v2.1 | MAAT, MAP | 1 км, климат. | GEE |
| GMTED2010 | elevation, slope, aspect | 250 м | GEE |
| SoilGrids 2.0 | soil_oc, soil_bd, soil_clay | 250 м | GEE |

## Параметры сетки

- **Bounding box:** 30°–180° E, 55°–78° N
- **Шаг:** 0.1° × 0.1° (≈ 10 км)
- **Размер:** 231 × 1501 пикселей (всего 346 731)
- **Валидных пикселей в России:** ~230 000
- **CRS:** EPSG:4326 (WGS84)

## Этап 1: выгрузка через GEE

Внутри ноутбука Google Earth Engine для каждого года 2010–2023:

1. Создаётся ImageCollection из спутниковых продуктов
2. Считаются годовые композиты (среднее, сумма, индексы)
3. Сэмплируются на сетку 0.1°
4. Экспортируются как Vector (GeoJSON) с Points

Из-за лимита GEE (32 МБ на запрос) экспорт разбит на:
- **band1** (10 признаков), **band2** (10 признаков)
- **west** (долготы 30–105°), **east** (долготы 105–180°)

Итого 14 × 2 × 2 = **56 файлов .geojson** размером ~30 МБ каждый.

## Этап 2: merge_geojson_bands.py

Скрипт читает .geojson и объединяет:
- west + east — по долготе
- band1 + band2 — по списку признаков

Итог: **14 merged.geojson**, по одному на год, со всеми 20 признаками.

## Этап 3: rasterize_to_tensor.py

Скрипт преобразует geojson → numpy:

1. Создаёт пустой массив (231, 1501, 20) с NaN
2. Для каждой Point-геометрии находит ближайший пиксель сетки
3. Записывает 20 значений признаков в нужную ячейку
4. Сохраняет с метаданными (lons, lats, feature_names, years)

Итог: `tensor_01deg_v2.npz` с массивом X (14, 231, 1501, 20).

## Этап 4: compute_ttop_target.py

Скрипт добавляет target:

1. Извлекает FDD = X[..., 7], TDD = X[..., 8]
2. (опционально) Строит landcover-карту и rk_map
3. Применяет формулу TTOP: `y = (rk * TDD - FDD) / 365`
4. Сохраняет y вместе с X в тот же .npz

## Проверка корректности

**Тестовая точка:** 104.6986° E, 55.2913° N (Прибайкалье, 2010 год):
- Из geojson: FDD = 3284.19, TDD = 1769.93 К·сут
- Из тензора: FDD = 3284.19, TDD = 1769.93 — совпадает
- По формуле: (0.7 × 1769.93 − 3284.19) / 365 = **−5.6034 °C**
- Из y: y[0, i, j] = **−5.6034 °C** ✓

Это подтверждает: **FDD и TDD в тензоре лежат в исходных К·сут**, без нормализации.
Это критически важно для пересчёта target с новым r_k.

## Что делать с эталонами

### Obu 2019 — отдельный скрипт `reproject_obu.py`

Берёт оригинальный TIFF (EPSG:3995, 1.8 ГБ) и через `rasterio.warp.reproject`
переводит на нашу сетку 0.1° (EPSG:4326).

### ESA CCI v05.0 — внутри ноутбука 04_validation

ESA CCI выгружается в NetCDF с разрешением 0.01° (≈ 1 км). Через `xarray.open_dataset`
и `interp` интерполируется на нашу сетку.

## Время выполнения

| Этап | Время |
|---|---|
| GEE выгрузка | 4–8 часов (фоновое в GEE) |
| merge_geojson_bands.py | ~10 минут |
| rasterize_to_tensor.py | ~5 минут |
| compute_ttop_target.py | ~2 минуты |
| reproject_obu.py | ~3 минуты |
| **Итого** | **~5–9 часов** (большая часть — выгрузка GEE) |
