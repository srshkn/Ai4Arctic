# Обзор проекта Ai4Arctic Frontend

## Общая информация

Ai4Arctic Frontend — это клиентское веб-приложение для интерактивной визуализации данных об изменении территорий вечной мерзлоты на карте России. Проект представляет собой одностраничное приложение (SPA), разработанное с использованием современного стека технологий, обеспечивающего высокую производительность, типобезопасность и удобство поддержки кодовой базы.

Приложение предназначено для учёных, экологов и лиц, принимающих решения, предоставляя удобный интерфейс для анализа многолетних данных о состоянии арктических экосистем. Пользователи могут переключаться между годами, фильтровать данные по типам мерзлоты и управлять видимостью отдельных слоёв температурного режима.

## Технологический стек

### Основной фреймворк и сборщик
- **React 18** — версия библиотеки для построения пользовательских интерфейсов с поддержкой хуков, Suspense и серверных компонентов
- **Vite 6** — современный инструмент сборки, использующий ES-модули для молниеносного горячего обновления (HMR) при разработке
- **TypeScript 5.6** — строго типизированный надмножество JavaScript, обеспечивающее обнаружение ошибок на этапе компиляции и улучшенный автокомплит в IDE

### Работа с картами
- **MapLibre GL JS 4.7** — библиотека с открытым исходным кодом для рендеринга интерактивных WebGL-карт с поддержкой тайловых карт, векторных слоёв и анимаций
- **@maplibre/maplibre-gl-style-spec 23.1** — спецификация стилей MapLibre для программной работы с конфигурацией карты

### Управление состоянием
- **Zustand 5** — лёгкое хранилище состояний на основе функций-создателей (stores), использующее React контекст и хуки. Значительно проще Redux и не требует boilerplate-кода
- Состояние разделено на несколько независимых сторов: `authStore` для авторизации и `mapStore` для параметров карты

### Маршрутизация
- **React Router DOM 6** — декларативная маршрутизация для React с поддержкой вложенных маршрутов, навигационных переходов и защищённых роутов через HOC ProtectedRoute

### Формы и валидация
- **React Hook Form 7.76** — библиотека для управления формами с минимальным количеством ререндеров благодаря использованию прямых рефов вместо контролируемых компонентов
- **Zod 3.25** — схема-валидация TypeScript-first, используемая как для клиентской валидации форм, так и для определения типов данных

### HTTP-клиент
- **Axios 1.16** — Promise-based HTTP-клиент с поддержкой интерсепторов для запросов и ответов. Используется для авторизации, обмена JWT-токенами и автоматического обновления access-токенов через refresh-механизм

### Стилизация
- **Tailwind CSS 3.4** — утилитарный CSS-фреймворк, позволяющий создавать стилизованные компоненты непосредственно в JSX с помощью классов
- **PostCSS 8** — инструмент для трансформации CSS с использованием JavaScript плагинов, используется вместе с Autoprefixer для автоматического добавления вендорных префиксов

## Ключевые архитектурные особенности

### Система аутентификации
Приложение использует JWT-аутентификацию с двойными токенами (access + refresh). Axios interceptor автоматически добавляет access-токен к каждому запросу. При получении HTTP 401 интерсептор пытается обновить токен через endpoint `/auth/token/refresh`. При неудачном обновлении сессия полностью сбрасывается и пользователь перенаправляется на страницу входа.

### Управление состоянием карты
Zustand store `mapStore` управляет параметрами карты (год, зум, центр), загрузкой GeoJSON данных и видимостью слоёв. Реализован механизм debounce (400мс) при переключении годов для предотвращения избыточных запросов. Поддерживается отмена предыдущих запросов через AbortController при быстром переключении. Кэширование загруженных лет предотвращает повторные загрузки одних и тех же данных.

### Работа с данными вечной мерзлоты
Данные хранятся в формате GeoJSON в директории `public/data/` как `magt_smooth_{year}.geojson`. Каждый файл содержит полигоны с атрибутами class_id (1-15) и color для каждого класса температурного режима мерзлоты. Цвета классов динамически извлекаются из GeoJSON при загрузке, что позволяет гибко настраивать визуализацию.

### Развёртывание
Сборка использует многоступенчатый Dockerfile: этап сборки на базе Node.js с выполнением `tsc && vite build`, затем копирование production-бандла в Nginx контейнер. Nginx раздает статические файлы и настроен как reverse proxy для API-запросов к бекенду.

## Скрипты разработки
- `npm run dev` — запуск development-сервера с HMR
- `npm run build` — компиляция TypeScript и production-сборка
- `npm run preview` — предпросмотр production-сборки локально
